# 配料表日期生成器

用于批量给配料表图片添加生产日期的 Windows 桌面工具。当前主版本采用 **Electron + React + TypeScript + Vite** 界面，图片处理使用 Python + Pillow。

## 当前默认参数

已经按实际配料表预览校准为：

```text
水平位置：13.9%
垂直位置：49.9%
日期字号：1.8%
自适应模板：开启
字体：黑体
字重：常规
字间距：-7%
```

坐标与字号默认不是相对整张截图计算，而是先自动识别每张配料表的外框，再相对各自标签区域计算，因此不同截图尺寸、边距和轻微裁切差异不会直接把日期带偏。

日期格式：

```text
2026 年 10 月 01 日
```

## 第一次：准备 32 张无日期模板

如果手里只有已经带日期的历史成品，不需要再人工截图 32 次。

1. 打开程序；
2. 点击 **“没有无日期模板？从历史成品一键生成”**；
3. 选择一个已有日期的成品文件夹，例如 `自营配料表\10月1日`；
4. 程序会在同级创建 `无日期模板`；
5. 只清除旧日期字符串，保留“生产日期:”与“保质期:3天”；
6. 生成完成后自动加载这 32 张模板。

模板图片与之后生成的图片都会完整保留原产品文件名，不追加日期或序号。

## 日常手动生成

程序会记住上次的模板文件夹、输出文件夹、定位方式和字体参数。

可使用：

- 今天
- 明天
- 后天
- 未来 7 天
- 自定义单日
- 自定义日期范围

每一天自动创建独立文件夹，例如：

```text
自动生成结果/
  9月21日/
  9月22日/
  9月23日/
```

## 自适应定位与字体

程序会逐张识别配料表的外层标签矩形，不使用 OCR。识别成功后：

- 水平位置按“标签宽度”计算；
- 垂直位置按“标签高度”计算；
- 日期字号按“标签高度”计算；
- 预览区会显示自动识别的标签范围和识别置信度；
- 点击预览图重新定位时，也会自动换算成标签内部相对坐标。

目前提供的字体参数：

- 黑体 / 微软雅黑 / 宋体；
- 常规 / 粗体；
- 日期字号；
- 字间距；
- 自适应定位开关。

所有参数都会自动保存。另外可以点击 **“保存方案”** 保存最多 12 套命名参数，例如“自营标准”“三方标准”，之后一键切换。



## 单张、多选与整批导出

右侧预览现在支持 **单张视图 / 网格视图** 两种模式。

网格视图可以：

- 勾选任意模板；
- 全选；
- 反选；
- 清空选择；
- 仅查看已选模板；
- 单击某张把它设为当前模板；
- 双击进入该模板的单张精细预览。

底部提供三种导出方式：

- **导出当前**：只生成当前预览的 1 张；
- **导出选中**：只生成网格里勾选的模板；
- **导出全部**：生成当前模板文件夹中的全部图片。

三种模式都支持单日和日期范围，并继续保持原产品文件名不变。

## 自动化中心

程序现在可以直接创建 Windows 计划任务。

可选择：

- 每天生成当天；
- 每天准备今明两天；
- 每天准备未来 7 天。

开启后会同时建立两类任务：

1. 指定时间每天自动运行；
2. Windows 登录时补运行一次。

因此电脑在设定时间未开机时，下次登录后仍会尝试补生成。

自动任务采用 **跳过已有文件、只补缺失图片** 的策略，不会重复生成已经存在的产品图片。自动任务也会使用当前保存的自适应定位、字体、字重和字间距参数。完成或失败时会使用 Windows 通知提示结果。

> 本地开发版也可以测试自动任务。移动项目目录以后，请在程序里重新点击“更新自动任务”，让计划任务指向新的项目位置。

## 最近生成与完整性检查

左侧“最近生成”会记录最近的日期结果，例如：

```text
2026 年 9 月 21 日   手动 · 32/32 张   完整
2026 年 9 月 22 日   自动 · 32/32 张   完整
2026 年 9 月 23 日   自动 · 31/32 张   需检查
```

可以直接点击每条记录打开对应日期文件夹。

程序也会在模板数量不是 32 张时主动提示，避免少图后继续误操作。

## 文件名规则

**生成后的文件名始终与模板产品名完全一致。**

例如：

```text
豆可滋   白干   净含量 2斤.png
豆可滋   嫩豆腐   净含量 5斤.png
豆小滋  嫩豆腐  净含量 12斤.png
```

不会变成：

```text
豆可滋白干_2026-09-21.png
图片1.png
9月21日-白干.png
```

## 本地开发运行

需要 Node.js 20+ 与 Python 3.10+。

```bash
pip install -r requirements.txt
npm install
npm run dev
```

开发模式不需要打包 EXE。

## 构建检查

每次直接更新 `main` 后，GitHub Actions 会自动运行：

- TypeScript 检查；
- Vite 构建；
- Python 语法检查。

这样即使采用“直接在 main 开发”的方式，也能尽快发现构建错误。

## 正式构建

```bash
npm run build
npm run start
```

## Windows 安装包

```bash
npm run package:win
```

## 分支约定

后续日常开发 **直接在 `main` 分支进行**，不再创建普通开发分支。
